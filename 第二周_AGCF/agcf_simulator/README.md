# AGCF 信令实验台

本地网页 + Python 标准库的离线原型。无需安装第三方包，不连接数据库，不向 SIP 地址发送信令。

## 打开与演示

1. 双击 `启动.cmd`，浏览器打开 `http://127.0.0.1:18766`。需要本机 Python 3.10+，优先使用当前 Codex 自带 Python。
2. 选择“普通开户呼叫”，点击“运行模拟”，查看输出 INVITE、下一跳、头域变化。
3. 选择“替换已有 PAI”，观察输入身份头域如何按人工配置映射被替换。
4. 选择“缺少注册信息”，观察流程停止且没有可转发输出。
5. “单步查看”会先完成一次计算，再逐步展示该次计算记录；不是向真实网元单步发包。
6. 点击“导出演示结果”，JSON 直接保存到程序目录的 `exports` 文件夹，页面显示保存路径。文件包含输入、配置、成功报文或失败原因、处理步骤和假设。修改输入后旧结果自动作废。
7. 完成后双击 `停止.cmd`，只停止本程序管理的进程。

也可以命令行运行 `python server.py --port 18766`，前台启动时按 Ctrl+C 结束。

## 两种页面的边界

**信令模拟**按照原始图片的“向主叫注册 S-CSCF 路由”要求构造演示：

- 人工指定入中继 38；从真实 CSV 快照读取 IOI。未根据 IP 四元组识别中继。
- 按 From 中的数字精确查找测试身份。新增用户只需修改 `data/demo_profiles.json`，或在网页“测试配置”中编辑 users 数组。
- 第一版只生成 PAI 和 PCV，PPK 待补充。带 PPK 的请求暂不支持；现有 PAI 按配置替换是本版策略，尚未经实际 AGCF 报文验证。
- PCV 不存在时用 UUID 生成 demo ICID；生成地址为测试地址。已有 PCV 必须有 icid-value，按本版策略保留，未实现全部 PCV 语法及可信域校验。
- `ioi_to_orig_ioi` 默认 true：IOI 使用真实值，但 IOI→orig-ioi 是可关闭的演示映射，不是已确认的厂商实现。
- 下一跳使用测试注册记录，并生成 Route。缺失注册时停止，绝不偷偷回退到 I-CSCF 静态路由。
- 简化代理式处理 Via、Max-Forwards、Content-Length，保留 Request-URI、To、From、Call-ID、CSeq 和消息体。真实 AGCF 可能采用更复杂的会话处理，本版没有宣称与之相同。
- 每次点击运行视为新的独立模拟，生成新的 ICID/branch；不实现 SIP 重传、事务去重、B2BUA、响应/ACK/BYE、媒体协商、注册流程、已有 Route 路由集或 re-INVITE。
- PUI `sip:+862132010323@sh2.ctcims.cn` 来自真实 B04 BRA 用户导出；它与 JSL TG38 的关系为跨来源人工绑定，不是一次已验证的现场呼叫。PUI 的使用规则仍是演示约定，不能由此判定真实设备最终使用原 PUI 还是新 PUI。
- `.invalid` 域名、192.0.2.0/24 地址、输入报文和用户注册状态均为测试数据。

**配置证据**仅探索同源数据库导出中的静态关联：TG38→CSC30→LP30→RSC10/RSSC30→ICSCF_ORIG。先按最长字冠匹配，再展示号长约束和主叫分析警告；不生成信令，不决定最终运行时路由。

- 保留 ADD/MOD 原始记录；没有根据 id 擅自重建有效配置。
- DNC 缺少 DCP 列、CNACLR 的 E 串通配编码尚待核实，因此不执行号码变换、不拼接未经确认的 PAI。
- 原始截图与静态 I-CSCF 配置可能属于不同处理场景，两者分开展示。

## 数据与实现

- `data/real_config.json`：从三个 CSV 提取的关联证据，带原文件 SHA-256、条数和 source_file。
- `data/demo_profiles.json`：可替换的身份映射、模拟注册及本机地址。
- `engine.py`：报文解析、规则执行、变化记录与静态证据查询。
- `server.py`：仅监听 127.0.0.1 的本地 HTTP 服务。
- `web/`：网页界面；无 CDN、外部字体或网络依赖。
- `build_snapshot.py`：原 CSV 更新后运行 `python build_snapshot.py`，自动核对汇总数量并重新生成快照。

快照来源：上级目录的 `同源链路配置.csv`、`号码分析配置.csv`、`主叫与号码处理配置.csv` 和 `样例数据/MSN 号码（主叫分机）new.csv`。身份样本单独保存，不与路由表做未经确认的真实关联。
参数解释依据：`链路参数说明.csv`、`号码分析参数说明.csv`、`主叫与号码处理参数说明.csv`，以及最初提供的 AGCF 流程图片。

SIP 头域结构参考 [RFC 3261](https://www.rfc-editor.org/rfc/rfc3261.html)；PCV 的 icid-value / orig-ioi 结构参考 [RFC 7315](https://www.rfc-editor.org/rfc/rfc7315.html)。协议结构参考并不能证明特定华为版本的处理规则。本版不是协议一致性测试工具。

## 验证

在本目录运行 `python -m unittest -v test_engine.py`。测试涵盖身份与被叫区分、真实身份值与人工绑定的来源区分、缺失注册、未知用户、已有头域、消息体字节长度、跳数限制、重复头域和静态最长前缀匹配。

后续有实际报文后，应增加同一次呼叫的输入/输出回归样例，再校准身份来源、号码变换、PCV 策略、路由及完整 SIP 行为。
